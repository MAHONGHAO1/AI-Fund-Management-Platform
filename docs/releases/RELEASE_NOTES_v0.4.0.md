# v0.4.0 · 指标口径与模拟数据边界修正

**发布日期**：2026-11-15
**类型**：正确性修复（含 4 个 P0 级口径错误）
**兼容性**：API 契约**有增量变更**（新增 `synthetic`、`metrics_available`、`history_capped`、`lookback_days`、`requested_days`、`available_days`、`coverage_start`、`coverage_end`、`truncated`），前端与后端须同版本部署。

这一版没有新功能。它修的是「界面显示的数值与它的标签对不上」这类问题——一个收益率数字写错单位、一个回撤漏算前期高点，比少一个功能严重得多。

---

## 为什么发这一版

在一次针对上线标准的自查中，两个独立审计视角分别检查前后端，交叉比对后发现：**多处指标的标签与算法口径不一致**。最典型的一条是「区间收益」按钮：无论点「近 1 月」还是「近 3 年」，显示的都是近一年收益率。数字本身没错，但它回答的不是用户问的那个问题。

下面按严重程度列出实际修掉的问题，每条都附带可复现的判定方式。

---

## P0：会给出错误数值的问题

### P0-1 区间收益始终显示近一年

**现象**：绩效页的区间切换只改了标题，数值恒为近一年收益率。
**根因**：前端 `intervalReturn` 从未读取所选区间；后端 `fund_history` 的回看窗口固定 460 天，选「近 3 年 / 全部」时也拿不到足够长的数据。
**修复**：
- 后端按请求区间换算回看窗口：`lookback = 3650 if days <= 0 else max(460, min(days + 45, 3650))`。
- 前端改用净值序列首尾计算区间收益，并在响应里返回覆盖度字段（`available_days` / `coverage_start` / `truncated`），当数据源不足以覆盖所选区间时，界面明说「数据源仅覆盖 N 天」，而不是把短区间当成完整区间展示。
- 「全部」区间不再伪造一个「请求窗口」：`requested_days` 留空，另设 `history_capped` 表达「已取满 10 年回看上限，可能还有更早记录」。这两种不确定性不是一回事，混成一个标志会让所有成立不足 10 年的基金误报「数据不完整」。

### P0-2 最大回撤漏算窗口之前的高点

**现象**：某基金净值距一年前的高点仍低 50%，页面显示「近一年最大回撤 0.00%」。
**根因**：峰值只在所选窗口内取 `max`。如果历史最高点在窗口之外，窗口内的下跌就不被计为回撤。
**修复**：峰值改为**全历史** `cummax`，再在所选窗口内计算回撤：

```python
peaks = series["nav"].cummax()
drawdown = window["nav"] / peaks.loc[window.index] - 1
```

新增回归用例 `test_max_drawdown_counts_peak_before_the_window`（构造 1.0 → 2.0 → 1.0 的序列，断言为 -50%）。

### P0-3 用模拟净值推算持仓金额

**现象**：数据源不可用时，应用回退到合成净值，并据此**改写**用户录入的持仓金额与累计收益。
**根因**：降级路径复用了正常路径的持仓更新逻辑。
**修复**：模拟净值下不再推算持仓，保留用户录入的快照金额；`analyze_fund` 统一走 `analyze_fund_with_mock` 单一出口，避免「降级了但指标照算」的半吊子状态。

### P0-4 前端自行从模拟净值算出收益

**现象**：后端刻意把模拟净值下的所有指标置为「不可用」，前端却用净值序列首尾自己算出了 `+21.30%`——同一屏里「最大回撤：不可用」和「区间收益：+21.30%」并排出现。
**根因**：修复 P0-1 时，前端获得了独立计算区间收益的能力，但没继承「模拟净值不算指标」的规则；仅靠比对来源字符串（`source === '模拟数据'`）这种松散约定。
**修复**：把可用性判定收进后端契约。

```python
"synthetic": nav_source.source == "模拟数据",
"metrics_available": nav_source.source != "模拟数据" and row.get("指标可用") is not False,
```

前端四张 KPI 卡统一走 `metricsUsable` 门禁，不再自己拼来源判断。新增用例专门喂一条「长得正好能算出 +21.30%」的模拟净值序列，断言页面**不出现**该数字。

## 前端可用性修复

- **历史净值三态**：加载中 / 失败 / 空区间分别呈现；失败时给出「重新读取」，不再永久停在「正在读取」。
- **持仓草稿保护**：切基金、切视图、刷新数据、恢复示例前，若存在未保存改动则二次确认。
- **导出报告**：改为 `fetch` + `Blob` 下载，失败时显示错误而非静默无反应。
- **表格行键盘可达**：`tabIndex` + `Enter` / `Space` 选中，`:focus-visible` 有可见焦点环；保留 `<tr>` 的行语义（不使用 `role="button"`，避免破坏表格结构）。
- **来源徽标四态**：实时 / 模拟 / 不可用 / **未知**。未知来源不再落进绿色「实时」分支。
- **回退状态中文化**：`none` / `synthetic` / `fallback` / `unavailable` 映射为「正常（未回退）」等中文，不再直出英文枚举。
- **数字输入允许负号**：输入框保留原始文本，`-` 不再被 `Number('-') || 0` 吞成 `0`；提交时统一收敛，空串按 0 处理。
- **图表无障碍**：每张图带 `aria-label` 与 `sr-only` 文字摘要（canvas 对读屏软件是空白）；`option` 用 `useMemo` 缓存并去掉 `notMerge`，避免每次渲染全量重绘。

## 已知边界（不是缺陷，是设计选择）

- **评分是池内相对排名，不是收益预测。** 9 只可评分基金里排第一，不代表它会涨。
- **模拟净值不产生任何指标。** 不是「算不出来」，而是「不该算」——合成数据算出的夏普比率没有任何信息量。
- **「全部」区间的历史上限是 10 年（3650 天）。** 顶到上限时会明确提示可能还有更早记录。
- **持仓只存在当前服务进程内存中。** 重启即恢复合成示例，不写本地文件。
- **服务只监听 `127.0.0.1`。** 不提供公网实例、不连接真实账户、不执行交易、不构成投资建议。

## 升级提示

本次为口径修正，**历史截图与旧版报告中的数值可能不再吻合**——那是旧版本算错了，不是新版本算错了。README 中的界面截图对应 v0.3.0 布局，数值口径以本版为准。
