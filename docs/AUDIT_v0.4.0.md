## 一、审计范围与方法

| 项目 | 说明 |

| 后端 | 指标数学口径、数据源回退、模拟数据边界、异常态、报告生成 |

### 「全部」区间语义（两次修正才定稿）

这一条经历了两轮反复，记录完整过程：

1. **初版**：`requested_days = int(days) if days > 0 else None`。审计指出：请求「全部」时若数据源只给到 3650 天，`truncated` 恒为 `False`，用户会把「数据源只有这么长」当成「这只基金历史上就这么多」。
2. **过度修正**：改成 `else lookback`（3650）。这引入更严重的问题——所有成立不足 10 年的基金都会误报「数据不完整」。
3. **定稿**：`requested_days` 在「全部」时留空；另设独立字段 `history_capped = days <= 0 and available_days + 10 >= lookback`，只在数据**顶满**回看上限时为真。

「你选的区间没取满」和「顶到了取数上限」是两种不同的不确定性，混用一个布尔量必然出错。

## 三、被推翻的判定

审计员不是权威，以下结论经复核后**撤下**。保留在文档里，是为了说明判定基准是什么。

| 审计结论 | 复核结果 |
| --- | --- |
| 前端「持仓金额 ¥0.00 假象」（原列 P1） | **不成立**。调用链 `holdings_to_map → safe_number_value → float()` 全程有限数，`or 0` 分支不可达。降级为 P2 并撤下措辞。 |
| 「模拟净值下近一年收益不可用」是规则而非巧合 | **部分成立**。当时是靠 2–4 天余量（`bdate_range(periods=260)` 实际跨 361–363 天）偶然成立的。已改为规则化：模拟净值一律不算任何指标。 |
| 「`apply_composite_scores` 已被改为 `None`」 | **不成立**。当前快照仍为 `float("nan")`。保留 `NaN` 是有意选择：数值列需保持 float dtype 才能排序与喂 plotly；出口由 `public_value()` 统一转 `null`。该策略已在 `public_value` 与 `DataProvenance` 的注释中写明。 |
| 「`filter_rows` 的 `is not None` 守卫无效」 | **描述已过期**。守卫早已改为 `math.isnan(to_float(...))`，但**判定本身仍然成立**——用 `isnan` 排除行和用 `is not None` 排除行，结果都是把不可评分行丢掉。已改为保留。 |
| 「测试 30 passed」和「测试 29 passed」并存 | 均为中间快照。定稿为 **34 passed**。 |
| 多轮报告「代码被并发修改、行号错位」 | 确认是本方在持续修复。已约定以「会话结束时的磁盘快照」为唯一基线。 |

## 五、仍存在的已知边界

这些不是未修的缺陷，是明确的设计边界：

- `history_capped` 只能表达「顶到 10 年回看上限」，无法区分「基金本身只有 10 年历史」与「数据源只给 10 年」。要精确区分需要数据源提供成立日期。
- 持仓仅存于服务进程内存，重启即恢复合成示例。
- 评分是池内相对排名。池子只有 2 只基金时，「第一名」的信息量接近于零。
- 前端图表为 canvas，无障碍支持限于 `aria-label` 与文字摘要，不具备完整的数据表替代视图。
