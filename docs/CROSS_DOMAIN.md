# 跨领域证据：同一个问题，两种数据

RoboData 和 Fund Lens 看起来是两个领域：一个是机器人操作数据集，一个是基金净值。它们共用的不是界面，也不是技术栈，而是一条更窄的主张：

> **一个数字能不能用，应该由来源、校验和失败路径决定，而不是由界面上的小数位决定。**

Fund Lens 在这里的角色是**跨领域验证**，不是第二个旗舰项目。它检验这套结构换一个领域后是否仍然成立；它不把 RoboData 的结论外推到金融，也不把金融数据的结论外推到机器人。

## 1. 同一条结构

| 结构 | RoboData | Fund Lens |
| --- | --- | --- |
| 固定来源 | 上游 revision `54141acb…` + Episode 0–4 SHA-256 清单 | 东方财富公开净值页 + 冻结日期与原始响应哈希 |
| 本地校验 | 下载后逐文件大小 / SHA-256 校验，导入时与固定清单交叉校验 | 读取时重算规范行哈希，和记录不一致就拒绝加载 |
| 失败可见 | 阶段报告写出失败阶段与原因，退出码非 0 | 五个回退状态（`none` / `fallback` / `fixture` / `synthetic` / `unavailable`），界面与报告都带来源和日期 |
| 不可用就说不可用 | 缺字段 / 覆盖不足时质检报问题，不静默补值 | 区间不够或来源失败时指标显示「不可用」，不用 0.00% 顶上 |
| 可复现交付 | `scripts/verify_pipeline.py` 一条命令跑完 8 个阶段，独立验证 ZIP | `scripts/verify_offline_fixtures.py` 进程内断网跑完 10 只基金与基准 |
| 明确不宣称 | 不证明训练效果、任务成功率、硬件同步、生产容量 | 不证明未来收益、策略有效、真实账户或生产可用 |

两边都把「证据」写成可重跑的命令和可核对的计数，而不是截图里的一个数字。

## 2. 两个可核对的样本

**RoboData（v0.11 验收）**：固定 revision 的完整 Episode 0–1，9 个文件 / 19,215,391 字节；导入 2 Episode / 1,300 帧；转换后官方 `lerobot 0.4.4` + `torch 2.7.1+cpu` DataLoader 读到 4 个 batch / 32 帧，动作与状态 `float32 [B,6]`、图像 `float32 [B,3,480,640]`。这是「官方训练加载器能消费交付物」的证据，不是训练效果。

**Fund Lens（v0.6 验收）**：10 只基金 / 9,943 行净值，5 个基准 / 6,097 行，15 个文件 / 1,124,931 字节，快照日期 2026-11-16 至 2026-11-18；断网验收中 10 只基金的收益、回撤、波动率、夏普与基准比较全部有值，HTTP 调用 0 次。这是「指标能从冻结公开数据算出来且来源可追溯」的证据，不是收益预测。

两个样本都很小，也都只覆盖一条路径。它们证明的是**流程和边界**，不是数据规模或领域普适性。

## 3. 不可互相外推的部分

- 机器人数据的「正确」是字段、形状、数值范围和加载器可消费；基金数据的「正确」是日期、复权口径、区间长度和基准对齐。两者没有共同的正确性定义。
- RoboData 的 1,300 帧不构成 SO-100 全量验收；Fund Lens 的 10 只基金也不构成基金池代表性。
- 两边都没有真实用户、真实账户或生产流量。Fund Lens 的持仓是虚构样例；RoboData 的审核标签是验收夹具。
- 冻结样本会过期。Fund Lens 的 `as_of` 是数据日期，不是「当前市场状态」；RoboData 的 revision 固定，但上游未来仍可能变化。

## 4. 面试时怎么讲

先讲问题，再讲两个领域各自怎么落地，最后讲边界：

1. **问题**：数据产品最常见的问题不是算错公式，而是不知道这个数从哪来、能不能用。
2. **RoboData**：把机器人数据集的下载、导入、质检、审核、转换、官方加载器消费和交付验证串成一条可重跑流水线；每个阶段留下哈希、计数和失败原因。
3. **Fund Lens**：把同样的结构迁到金融数据；五个回退状态让「实时 / 备用 / 冻结 / 模拟 / 不可用」在界面和报告里可区分，冻结样本被改动会失败关闭。
4. **边界**：两个项目都只证明流程与证据，不证明策略成功或生产容量；这正是它们可以作为作品集、但不能包装成生产系统的原因。

如果要看每一项的原始计数和复现命令，以两个仓库各自的 `docs/EVIDENCE.md` 为准；这份文档只负责解释它们为什么放在一起。
